# 复核记录与最终交付检查

状态按阶段区分：缺资料或主动草稿为 `draft`；组装完成为 `assembled`；缺复核或版本不匹配为 `review-pending`；资料和复核齐全、版本一致时为 `submission-ready`。最后状态只代表记录检查通过；调用模型仍负责真正完成核验，不得编造检查结果。

## 流程

1. 清点资料图表，把需要看图的资料页/局部图列入 `visual_sources`；记录真实数据输入 `data_files` 和计算结果 `result_files`。照片、报告中图像也将纳入检查。
2. 执行计算/绘图源码，保存结果和实际命令/退出状态；通过结果占位符组装报告。
3. 导出最终 DOCX 页面，保存全部页面图像。Windows 可用 `render_word.ps1`；其他环境使用已有文档渲染工具。图片只作为内部质量检查，不冒充实验数据照片。
4. 初始化待复核记录。所有检查默认 pending，不自动通过：

```powershell
python finalize_report.py report.json report.docx --quality quality.json --init-quality --pages qa/page-1.png qa/page-2.png --code analysis.py
```

`report.json` 和 `report.docx` 命令参数相对调用目录；`--pages`、`--code` 和 quality 内文件路径相对 report.json 所在目录。最好在报告工作目录运行；初始化不覆盖已有 quality 文件。

5. 当前模型实际查看每张资料/数据图和每页最终渲染图；核验完成后填写检查结果、差异及证据。验证数值和单位，填写执行记录，检查交付文件齐全。
6. 执行最终检查：

```powershell
python finalize_report.py report.json report.docx --quality quality.json
```

输出 submission-ready 且退出码 0 才可称为可提交；其他状态退出码 1，按列出的缺项修复。不要为使检查通过而删除必要图像、缩减来源清单或改写质量记录。仍缺材料时直接交付标记清楚的草稿。

## 交付目录和收尾清理

最终根目录仅有 `<实验名>_实验报告.docx`、`说明文档.md`（或用户指定格式）、`图片/`、`代码/`。图片包含正式图及报告实际使用的原始照片副本；源码在代码目录，必需复现数据和报告绑定所需最终结果在 `代码/数据/`，必要自定义模板在 `代码/模板/`。最终 `delivery_files` 要包含说明和图片，以及检查器要求的源码、数据/结果/自定义模板；不要把内部工作文件充当交付文件。

生成/复核所需 report.json、quality.json、渲染 PDF、页面 PNG、渲染缓存和日志放在交付目录之外的本次临时目录。先完成当前版本检查，确认说明中有实际复核摘要和运行命令，再清理本次生成且已不需要的临时文件；清理后检查最终清单和实际文件一致。该收尾检查不是要求重新生成已删的内部页面截图，也不能用清理操作掩盖尚未完成的复核。

不要删用户原件或未知文件；目录递归删除前核实解析后的绝对路径属于本次临时工作范围。项目自身的 qa、tests、docs 和安装包不是运行某次报告时的待清理中间产物。需要保留的复现输入和最终计算结果即使为 CSV/JSON，也属于代码目录内的必要交付内容，不与临时组装 JSON 混淆。

图题位于图下，表题位于表上；两类补充注释均位于对应图表之后。逐页视觉检查题注是否相邻、是否被独立推至下一页。

## 字段与证据

排版复核须检查中文宋体、西文新罗马体、二号主标题、小三一级标题、小四正文、分级字号/强调、居中且无下划线的班级、姓名、学号、座位号四项个人信息、正文两字符缩进及两端对齐。逐一检查居中三线表、五号加粗居中的中文图表标题及紧跟图表的小字加粗注释。全部渲染页记录是否有大面积空白、孤立标题/题注/注释；有问题先通过段落间距、图表位置、大小和排布调整，再重新渲染并复核。不能仅核对 DOCX 样式属性就填“视觉排版通过”。

组装版本 2 自动记录实际模板路径，并将其内容纳入文件指纹；默认模板和命令行模板均受版本检查。命令行自定义模板即使没有重复写入 `template_file`，初始化清单仍会加入模板核验和交付项。旧版缺少实际模板记录的报告应重新生成。最终检查对照 JSON 中每部分的公式块数量，拦截公式被删除或移到其他部分的情况；数量检查不能替代公式含义的视觉核验。

- `report_sha256` / `input_sha256`：初始化时生成，与该次生成的 Word 和标准化输入绑定。
- `vision_reviews`：每个资料图表、照片、生成图和最终渲染页均需记录 `path`、`sha256`、`reviewer: current-model`、实际检查项目 `checks`、`evidence`、`status` 和未解决项 `unresolved`。证据写实际图片查看操作/页码/区域及逐项核验结果，不写笼统的“已检查”。原资料页对应关系和差异可附在记录中。
- `artifact_checks`：实际计算输入和结果文件的指纹、核验说明与状态。复核表头/单位、输入范围、结果与代入过程的一致性。
- `calculation_review`：当前模型结合执行结果核验物理模型、单位换算、代入值、关键结果、有效数字、适用的不确定度和图上关系；记录 reviewer、evidence、status、unresolved。
- `layout_review`：当前模型实际看过最终所有页面后记录 reviewer、pages、page_count、evidence、status；检查公式、图注、字体、图像、表格和分页。pages 必须包含全部实际页面；最终报告须为 10–20 页，检查器拦截范围之外的页数。工具检查声明页数与清单一致且文件有效，不能替你确认漏页或截图是否来自真实报告，必须对照完整渲染文档核实。
- `execution_records`：实际使用的 `.m`/`.py` 源码路径、指纹、真实命令和退出码。只有实际成功执行才能填 0；生成当前计算结果、正式图像和自定义报告的必需脚本应全部记录。失败但已由其他成功方案替代的尝试只保留在运行日志，不用 `--code` 纳入此清单。附带但未执行的源码只加入交付清单并注明未执行；若必需源码未成功执行，保持待复核状态。生图降级也必须有成功执行的数值计算源码；生图工具调用记录另列证据，不能伪造为 `.m`/`.py` 执行。
- `delivery_files`：报告、实际源码及复现所需数据文件。可另附简短运行命令；目录结构和代码相对路径需一致。质量页面图像无需作为正式交付物。
- 顶层 `unresolved`：所有未解决的问题。没有解决时保持相应记录 pending/failed，不能填通过。

发现错误时修正源数据或代码，重新计算、绘图、组装和渲染，再针对新版本复核。最终检查会比较 Word 内的组装指纹与当前输入/结果/图像，不能通过“更新质量文件的哈希”让仍引用旧结果的 Word 放行。不要手动改写 Word 组装元数据；自定义模板或复杂公式处理应保留生成记录，最后整体重新核验。

该工具不提供 OCR 正确性、科学正确性或看图操作真实性的自动证明。机器可检查的是完整性、文件对应关系和版本一致性；实际证据必须由当前模型按真实执行记录填写。

无题目豁免由报告输入 `questions_provided: false` 控制，最终结果返回 `delivery_notes: ["未提供思考题"]`。必须把说明写在聊天交付消息或单独说明文件中，不插入报告。此说明不是 unresolved，不妨碍其他检查全部通过后的 submission-ready。

自定义模板使用 [custom-template.md](custom-template.md) 的生成与验收路径。生图块使用 `source: imagegen`，最终检查从 Word 嵌入图像和实际尺寸计算 dpi，要求元数据及有效 dpi 均至少 300；原始像素未被插值伪造和逐点数值准确性仍需模型核验证据。


## 最新符号与说明检查

正文仅写实验内容、推导计算和数据支持的分析。资料识读、适用性声明、讲义/照片差异、符号命名依据、来源映射、存疑项、运行或排版解释全部放说明文档，不在正文、图表注释或脚注中插入“适用于本次资料”“本报告按原始照片与讲义分别识别为……”等过程说明。科学原理和结果解释仍保留。来源须可追溯；说明文档记录资料文件/页码/照片区域→测量值/物理量→统一符号/单位→结果和图表。全篇同一物理量统一名称、上下标、单位、数值与有效数字；不按不同资料的字形混用符号。不能确认的关键值不猜定，存疑只记说明文档，影响结论时仍保持草稿；不把疑点隐藏后当成已确认结果。草稿状态及缺项写说明/文件名，正文保留空栏而不插入处理提示。

中文及所有标点（包括英文标点、括号、引号、逗号、小数点等）使用宋体；西文字母和数字使用 Times New Roman。文档正文、标题、图表标题/注释及可编辑表格中的全部字母、参数和公式使用 Word 原生公式对象，短变量也使用行内 OMML，上下标使用结构化公式，不用普通文字、Unicode 上下标或图片替代。绘图/原始照片内部的文字是图像内容，无法成为 Word 原生公式：正文引用其符号及单位须用 OMML，原始照片不改写。图中字体和符号仍须与全文一致。

检查器会拦截普通文段中的西文/希腊字母和非宋体标点；语义一致性、来源真实性、说明移出正文仍由当前模型实际核验，不能只依赖正则检查。
