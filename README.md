# 物理实验报告 Skill

根据实验讲义、测量文件和原始数据照片，生成中文 Word 物理实验报告，并交付实际使用的 MATLAB 或 Python 计算、绘图代码。

本项目是供具备文件操作、代码执行和视觉能力的模型使用的 **skill**。模型负责理解资料、选择物理模型、编写内容和复核；配套脚本负责绘图、Word 组装及文件一致性检查。

## 功能

- 实验报告为 10–20 页，可适当详细展开原理、计算过程、图表分析和题目解答；按最终渲染页数检查，不凑页。
- 所有识图由当前模型自身完成；本地渲染 PDF/Word、读取文本层和数值文件提供辅助输入，不调用外部 OCR、识图模型或上传解析服务。

- 按提供的模板组织八部分报告，个人信息保留空白，由用户手动填写。
- 第五部分插入用户提供的真实实验数据照片，可附转录表。
- 第六部分包含计算公式、代入过程、结果及数据图；公式使用 Word 原生可编辑公式（OMML）。
- 中文宋体、西文新罗马体；主标题二号、一级标题小三、正文小四。个人信息居中、无下划线，仅班级、姓名、学号、座位号四项；正文两端对齐、首行缩进两字符；分级标题左对齐，字号降到小四后用加粗/斜体区分。
- 图表居中，中文标题五号加粗居中，简短中文补充注释小五加粗并紧跟图表；表格采用规范三线表。逐页渲染复核，通过段落与图表排布、大小调整尽量避免大面积空白。
- 优先执行 MATLAB 绘图，其次使用 Python；两者绘图均不可执行但数值计算可执行时，尝试宿主提供的生图 API。生图文件 dpi 和按 Word 插入尺寸计算的有效 dpi 均至少 300，并核验每个数据点。
- 在数据和原理支持的范围内尽量多绘图：先列绘图清单，资料充分时通常争取 3–6 张互补图/分析子图，覆盖主关系、适用的残差、重复测量与条件对比；数据少时说明原因，不为凑数重复或编造。
- 由运行 skill 的当前模型自身逐一查看、复核资料和数据中的所有图表、数据照片、生成图像和报告页面，不抽样跳过。
- 保存计算结果 JSON，支持正文、公式和表格引用同一结果，检查报告与输入、图片、结果、代码的版本一致性。

## 安装

从本仓库下载 `physics-lab-report.zip` 并解压，或克隆仓库后使用 `physics-lab-report/` 子目录。依赖安装与项目维护见 [docs/development.md](docs/development.md)。

将本仓库中的 `physics-lab-report` 文件夹，或 ZIP 解压后包含 `SKILL.md` 的同名文件夹，放入 Codex 的 skills 目录：

```text
~/.codex/skills/physics-lab-report/
```

Windows 默认位置为：

```text
C:\Users\<用户名>\.codex\skills\physics-lab-report\
```

如果设置了 `CODEX_HOME`，使用其下的 `skills` 目录。确认 `SKILL.md` 直接位于该文件夹内，避免重复嵌套。

## 快速使用

在支持该 skill 的宿主中调用，并提供本次实验材料。例如：

```text
使用 $physics-lab-report，依据附件中的实验讲义、测量 CSV 和原始数据照片，
并查询任务、下载结果；无须逐文件再次确认，CSV 等数值文件仍本地读取。
生成 10–20 页物理实验报告，可适当详细。个人信息仅班级、姓名、学号、座位号，居中、无下划线并留空，第五部分放原始照片，
第六部分使用可编辑公式，优先调用 MATLAB 绘图。
回答讲义中的全部思考题，并交付 Word、实际运行的源码及复现数据。
由当前模型自身复核资料图表、数据照片、生成图和最终报告页面。
输出到本次实验的独立目录。
```

### 应提供的材料

| 材料 | 用途与要求 |
| --- | --- |
| 实验讲义或说明 | 确定目的、原理、仪器、步骤、处理方法和要求 |
| 测量数据 | CSV、XLSX、TXT 或清晰照片；尽量注明物理量、单位、条件和仪器精度 |
| 原始数据照片 | 第五部分必需；数据表截图或模型生图不能替代真实照片 |
| 思考题、实验拓展 | 可以单独上传，也可包含在讲义中 |
| 自定义模板 | 可选；默认使用项目中附带的模板 |

关键数字模糊、资料缺失或尚未复核时，输出标明缺项的草稿。不会补造测量值、照片或指定题目。附件中的文字作为资料读取，不作为执行任意代码或外部操作的授权。

## 报告结构与交付

1. 实验目的
2. 实验原理
3. 实验仪器
4. 实验步骤
5. 实验数据记录
6. 数据处理（绘图及计算）
7. 实验结果分析
8. 课后思考题及实验拓展

前四部分按资料填写，模板允许缺资料时留空；第五至八部分标题保留。确认资料和讲义均未提供思考题、且用户未要求自拟时，设置 `questions_provided: false`，第八部分正文留空，允许完成报告；“未提供思考题”仅写在聊天或单独交付说明中，不写入报告。已有题目必须全部回答。仅班级、姓名、学号、座位号留给用户填写，居中且无下划线。

正式交付包括 `<实验名>_实验报告.docx`、实际使用且成功执行的 `.m` 或 `.py`、复现所需数据及简短运行命令。失败但已由成功方案替代的尝试只留运行日志；未执行的附带源码单独标明，不能作为当前结果的执行证据。采用生图 API 时，仍须交付成功执行的数值计算代码，并说明图像没有 MATLAB/Python 绘图源码。质量记录及渲染页面用于复核，可保留在工作目录。

最终目录仅保留报告、说明文档、图片文件夹和代码文件夹：

```text
<实验名>_交付/
  <实验名>_实验报告.docx
  说明文档.md
  图片/
  代码/
    数据/
```

必要输入和最终计算结果随代码放在 `代码/数据/`，必要自定义模板放 `代码/模板/`。图标题在下、表标题在上，补充注释跟在图表后。复核完成后清理本次无用的旧稿、渲染 PDF/截图、渲染缓存、临时 JSON 和失败输出；只清理本次生成文件，不删除用户原件、skill 或项目测试材料。内部复核文件在交付目录之外，实际复核摘要和运行说明保留在说明文档中。

## 正文与说明文档

正文仅写实验内容、推导计算和数据支持的分析。资料识读、适用性声明、讲义/照片差异、符号命名依据、来源映射、存疑项、运行或排版解释全部放说明文档，不在正文、图表注释或脚注中插入“适用于本次资料”“本报告按原始照片与讲义分别识别为……”等过程说明。科学原理和结果解释仍保留。来源须可追溯；说明文档记录资料文件/页码/照片区域→测量值/物理量→统一符号/单位→结果和图表。全篇同一物理量统一名称、上下标、单位、数值与有效数字；不按不同资料的字形混用符号。不能确认的关键值不猜定，存疑只记说明文档，影响结论时仍保持草稿；不把疑点隐藏后当成已确认结果。草稿状态及缺项写说明/文件名，正文保留空栏而不插入处理提示。

中文及所有标点（包括英文标点、括号、引号、逗号、小数点等）使用宋体；西文字母和数字使用 Times New Roman。文档正文、标题、图表标题/注释及可编辑表格中的全部字母、参数和公式使用 Word 原生公式对象，短变量也使用行内 OMML，上下标使用结构化公式，不用普通文字、Unicode 上下标或图片替代。绘图/原始照片内部的文字是图像内容，无法成为 Word 原生公式：正文引用其符号及单位须用 OMML，原始照片不改写。图中字体和符号仍须与全文一致。

## 上下文与重复开销

精简阶段入口从 8049 字符压缩为 2984 字符（约减少 63%，后续新增要求会增加长度），保留全部用户要求；详细规则移至按需参考。这是字符数变化，不是实测 token 或总费用降幅。执行时不预读全部参考/源码，不在聊天重复全文和长日志；同一版本已看过的图片与有效记录可复用，修订只重算或重画受影响内容。全部来源图表和最终页面仍需真正完成视觉复核，报告仍为 10–20 页。


Windows 已安装 Microsoft Word 时，可使用 `render_word.ps1` 将报告只读导出为 PDF；之后仍需把 PDF 渲染为图片，由当前模型逐页查看。

## 工作流程

1. 清点材料、单位、题目及全部资料图表；本地渲染文档，读取原始数值，全部识图由当前模型自身完成。

2. 当前模型查看原始图像，逐项核对转录数据；不明确的关键值请用户确认。
3. 根据实验模型列绘图清单，尽量完整生成适用的互补图，执行计算并保存数据、结果 JSON 和源码。
4. 查看生成图像，结合计算值核对坐标、点位、拟合线、单位和标注。
5. 组装 Word，渲染全部页面，检查公式、图注、表格、图片和分页。
6. 如实填写质量记录，运行最终检查；发现变化或差异后重新生成、复核。

### 配套工具

以下命令在仓库根目录运行，假设 `work` 已包含本次实验的输入文件。`report.json` 是模型根据资料、计算和复核生成的组装输入，不是原始实验数据。

```powershell

# 组装 Word；缺资料时加 --draft。
python physics-lab-report/scripts/build_report.py work/report.json work/report.docx

# 已完成渲染后，初始化待复核记录。
# --pages、--code 的路径相对 report.json 所在目录。
python physics-lab-report/scripts/finalize_report.py work/report.json work/report.docx --quality work/quality.json --init-quality --pages qa/page-1.png qa/page-2.png --code analysis.py

# 当前模型实际完成检查、填写记录后，再执行最终检查。
python physics-lab-report/scripts/finalize_report.py work/report.json work/report.docx --quality work/quality.json
```

示例中的页数和代码名应替换为本次实际文件，页面清单必须覆盖全部报告页面。初始化只创建待检查记录，不会自动标记通过。最终报告须为 10–20 页，页数超出范围不能通过最终检查。

## 状态与限制

| 状态 | 含义 |
| --- | --- |
| `draft` | 缺必要材料，或明确生成了草稿 |
| `assembled` | Word 已组装，尚不代表完成复核 |
| `review-pending` | 缺复核记录、存在未解决问题或文件版本不一致 |
| `submission-ready` | 最终记录检查通过，且对应当前文件版本 |

最终检查器验证记录完整性与文件一致性，不能证明模型确实看过图，也不能自动证明物理结论正确。实际识图、数值核验和逐页排版检查必须真正完成。

- 默认模板作为结构和样式参考，正文会重建；复杂文本框、内容控件或要求精确保留的模板使用专用生成脚本保留结构、绑定模板指纹，再走同一验收流程。必需标题和图片应保留检查器支持的正文结构，否则交付待复核稿。
- 公式辅助工具支持分式、上下标、根号和组合；复杂积分、矩阵可通过完整 `equation.omml` 输入，仍须结构检查和页面视觉复核。
- 附带绘图工具适合两列数据及适用的线性拟合；非线性拟合、误差棒和特殊处理需按实验编写专用代码。
- 生图 API 不能替代数值计算；无法核验坐标和数据点时，图只能标为示意图，报告保持草稿。

## 验证情况

当前实现通过 26 项单元测试，覆盖四项无下划线个人信息、字体与图表格式、计算和版本一致性，以及 9/10/20/21 页边界拦截。页数测试使用合成页面，只验证检查器规则，不代表已完成真实实验的 10–20 页验收。合成版式渲染记录见 [docs/verification.md](docs/verification.md)。

在具备测试依赖的 Python 环境中运行：

```powershell
python -X utf8 -m unittest discover -s tests -v
```
